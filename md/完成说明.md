# 十道题实现说明

`md/2.md` 至 `md/11.md` 的实现位于产品 `src/`，可以通过题目规定的 Python 接口调用。

| 题目 | 入口 | 实现行为 |
| --- | --- | --- |
| 2：CSV 行级采集 | `powercontext.sources.csv_rows` | 严格 UTF-8/BOM 与 CSV 解析，完整文档原子校验，主键稳定身份，原列序、原字符串投影及持久化回查。 |
| 3：Pi 会话历史 | `powercontext.sources.pi_session` | 验证完整 v3 图，沿所选叶节点提取原始可见事件，完整保留工具正文，通过 ConnectorLifecycle 保存去重与历史改写校验信息。 |
| 4：PDF 全文与页检索 | `powercontext.sources.pdf_pages` | 用 pypdf 解析全部物理页，保留空白页、文档摘要与修订身份，通过 scoped Memory 的公开接口读取当前页记录并进行离线 BM25 排序。 |
| 5：HTTP 重排 | `powercontext.builtin.artifacts.memory.http_reranker.HTTPMemoryReranker` | 使用调用方 AsyncClient 分批请求，全局 rank 不重编号，严格验证响应，全池稳定排序，报告实际请求数。 |
| 6：增量上下文 | `powercontext.builtin.runtime.context_pack`；`context.for_scope(...).prepare_incremental(...)` | 确定性 UTF-8 分块，规范 Base64/JSON、摘要和完整字节数校验，序列化后可独立重建目标正文。 |
| 7：数量触发 | `RuntimeConfig`；原生 ArtifactProcessingSupervisor | 两个默认关闭的严格正整数门槛。按各 scope、family 的成功 cursor 与 journal head 计算数量，与时间条件采用 OR，保留 Memory 单窗口与 Topic wave 的原有消费和失败恢复行为。 |
| 8：Embedding 合并 | `powercontext.builtin.inference.coalescing.CoalescingEmbeddingModel` | 合并窗口与执行中请求共享，批量去重，有界 LRU，保持输入顺序、重复位置、批次 usage、失败重试和取消隔离。 |
| 9：来源生命周期 | `runtime.lifecycle.for_scope(...)` | 持久化依赖 DAG、原始引用与事件，传播 all/any 可用性，使用原生 Memory 停用和恢复，过滤不可用 Topic，支持审计和中断重试。 |
| 10：证据选择 | `PrepareContextRequest(evidence_selection=True)`；`PreparedContextBuild.fragments` | 查询加权的原文句子选择，保留小数和精确字符区间，跨 scope 引用分离，合并相邻片段，按完整 envelope 的 UTF-8 字节数控制预算。 |
| 11：seekdb 混合检索 | `powercontext.builtin.persistence.seekdb.memory_index.SeekDBMemoryIndex` | 一条 UNION ALL statement 获取两路原生候选，数据库内应用过滤与候选上限，沿用当前 head 校验和既有融合逻辑。 |

## 使用与兼容

三个 Source Definition 通过 `SourceDefinitionRegistry` 显式注册，并使用既有 manifest、observation 和 Runtime ingestion 接口入库；不需要改动生成的 HTTP API 文件。

数量触发使用如下配置：

```python
RuntimeConfig(
    memory_source_count_threshold=3,
    topic_memory_source_count_threshold=3,
)
```

关闭证据选择、数量门槛或未采用 Embedding 包装器时，继续使用原有路径。生命周期注册保持原始正文引用；撤回和恢复不会创建新的正文版本。新增生命周期关系表随数据库初始化创建，旧的不可变证据仍按原引用读取。

PDF 搜索会读取当前作用域的全部活跃页记录，计算本次问题的词项统计；其读取和排序成本随页数增长。数量触发按有界页面读取 dirty scope 的 journal 和 cursor 元数据，不读取 Source 正文。生命周期事件会遍历并保存该 scope 的依赖图，适用于题目规定的每 scope 16 至 20 节点规模。

## 复现公开验收

在 Linux x86_64、Python 3.12 环境安装 `competition/requirements.txt` 后，从仓库根目录执行：

```bash
export POWERCONTEXT_CANDIDATE="$PWD"
export POWERCONTEXT_PUBLIC="$PWD/competition"
export PYTHONPATH="$POWERCONTEXT_CANDIDATE/src:$POWERCONTEXT_PUBLIC"
export PYTEST_DISABLE_PLUGIN_AUTOLOAD=1

for task in \
  source-01-table-evidence source-02-pi-history source-03-pdf-retrieval \
  retrieval-01-reranking context-02-incremental-pack processing-01-count-trigger \
  memory-02-embedding-batches memory-01-source-lifecycle \
  context-01-evidence-selection retrieval-02-hybrid-search
do
  python -m pytest -q -c competition/pytest.ini --confcutdir=competition \
    "competition/challenges/$task/acceptance" || exit 1
done
```

Pi 的公开 JSONL 样例包含固定字节摘要，`.gitattributes` 为该样例保留 LF，避免 Windows 自动换行转换改变文件摘要。

新增的 `tests/test_evidence_extensions.py` 覆盖原文小数、跨 scope 身份、协议非法输入，以及真实 SQLite 写入中断后的生命周期重启重放。

## 验证结果

Linux x86_64、Python 3.12 与比赛锁定依赖下，十组公开验收共 **95 项全部通过**，未跳过测试。

| 公开验收组 | 通过数 |
| --- | ---: |
| CSV | 17 |
| Pi | 15 |
| PDF | 6 |

seekdb 使用真实 `pylibseekdb==1.3.0.post4` 执行，验收包括单候选 SQL、EXPLAIN 中的全文与向量索引、过滤、当前版本引用及停用恢复。PDF 公开验收完整解析并持久化 503 页。

另外，132 项现有相关回归测试与 8 项新增边界测试通过。改动文件通过 Ruff 检查和格式检查；全部 `src/` 通过仓库锁定的 ty 0.0.56 检查，静态目标平台为 Linux。
