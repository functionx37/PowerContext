# 验证记录

## 已完成的真实验证

- `npm test`：5 项通过，覆盖 Unicode 分块不丢字、稳定内容 ID、去重后的 Recall/nDCG、向量维度/数值/模型指纹校验、数据库连接队列错误恢复及禁止交错。
- `npm run build`：TypeScript 类型检查与 Vite 生产构建通过。推理 Worker 与 ONNX Runtime Web WASM 独立打包。
- `npm run test:db`：对运行中的真实 seekdb 执行建集合、写入、重复导入去重、显式刷新、数据库混合检索、两个集合并发隔离、完整原文读取、统计和错误向量拒绝，全部通过。原始记录在 `reports/db-smoke.json`。该测试的单位向量仅是接口测试夹具，从未作为应用推理/质量/性能结果。
- 浏览器：INT8 自动选择 WebGPU 加载成功；强制 WASM/INT8 后，18 篇示例文档真实向量化，写入计数 18，显式刷新成功。
- 浏览器：查询“如何让刚刚写入的资料马上可以被查询到？”经 seekdb 混合检索返回 5 条，第一条是“索引刷新.txt”；观察到向量化 36 ms、数据库检索 303 ms、端到端 425 ms（包含首次数据库混合查询开销）。点击“查看原文”成功读取 seekdb 保存的完整原文。
- 完整评测：FP32/WASM batch1、FP32/WASM batch8、INT8/WASM batch8、FP16/WebGPU batch8，各 3 次独立集合导入、36 次真实混合查询；144 个查询均保留原始排名和计时。
- 模型三份 ONNX 文件均由下载脚本验证 SHA-256 与长度。模型准备共 166,800,479 字节（含三份权重及共享文件）；各精度独立部署大小见技术说明。
- 重启后知识库及 18 个片段仍保留；模拟 WebGPU 不可用时，默认 FP16/自动配置实际切换 WASM/INT8，界面显示测试模式原因。再次导入相同示例跳过 18 块、插入 0 块，刷新仍成功。
- 自动降级后查询“如何结合关键词和语义搜索进行统一排序？”返回“混合检索.txt”为首条；向量化 35 ms、seekdb 288 ms、含首次模型加载和绘制机会的端到端 669 ms。截图见 `docs/preview.jpg`。

## 性能解释

机器：AMD Ryzen 7 7840HS with Radeon 780M Graphics；GPU：AMD Radeon(TM) 780M；物理内存 29,867,585,536 字节，约 27.82 GiB。浏览器报告的 deviceMemory=32 是提示值，不代替物理实测。内置浏览器 User-Agent 为 Chrome/156.0.0.0，见原始 JSON。模型 FP32/FP16/INT8 均为固定公开 revision；seekdb 实测版本 `5.7.25-OceanBase seekdb-v1.4.0.0`，WASM 单线程。

完整评测中，`requestAnimationFrame` 回调出现约 1 秒周期。端到端计时包括该回调，原始数据约 1002 ms；分阶段模型/数据库计时远小于此值。这与内置浏览器后台/自动化帧节流一致，但未获得浏览器调度器的独立证据，因此属于推断。保留原始数值，不扣除固定偏移或冒称推理瓶颈。请在前台原生 Chrome/Edge 重新运行评测，再比较用户可感知延迟。

FP32 batch1→batch8 同时改变批处理和刷新策略，整体导入从 8.40 秒降到 2.16 秒；主要收益来自减少刷新和写入开销。FP32 batch8 的向量化吞吐比逐条略低，本机本语料没有证据表明批处理本身更快。FP32 batch8→INT8 batch8 固定其他配置，是精度单项对比。WebGPU 方案同时改变精度与后端，仅作实际部署方案比较。

每次加载记录本机资源读取及运行时 session 创建，第一次推理单独记录。模型网络下载经过镜像限流、重试和断点续传，未保留完整冷下载时长；不提供虚构的下载速度或耗时。模型体积来自本地文件逐个 stat 和 SHA-256，具有可复核口径。正式较大语料验收仍应补充前台浏览器冷下载与端到端延迟实验。

## 复现降级

默认 FP16/自动后端。使用 `http://localhost:3000/?webgpu=off` 可在 Worker 的 GPU 探测入口模拟适配器不可用，不修改操作系统或浏览器设置。界面明确标注“测试模式”，自动使用 WASM/INT8。也可手动选择“WASM · 强制降级”。该测试模式不代表在没有 GPU 的独立物理机器上验证。

## 范围

本次真实数据库与浏览器链路使用 Windows 嵌入式模式；Docker Compose 为按官方部署接口提供的备用配置，未在本次实验中启动数据库容器。应用不含图片检索扩展、用户账号或在线部署。文档更新保留旧内容为另一版本，不提供自动替换旧版本的文档管理功能。

Windows 原生组件会影响进程标准输出，开发服务将后续日志写入 `.data/application.log`，避免 Vite 热更新时触发 EBADF；启动地址仍在首次初始化前输出。该兼容处理只对 Windows 嵌入式模式生效。
